## 使用者情境與測試

### 使用者故事 1：對局中辨識狙擊者（優先級：P1）

玩家選擇狙擊者進入對局後，可以看到具有低矮細長輪廓、長槍與瞄具的偵察狙擊兵像素角色；角色會依瞄準方向顯示八個面向，移動與成功攻擊時播放一致的角色動畫。

**優先原因**：對局中的角色辨識、方向判斷與攻擊回饋是這次外觀更新的主要遊戲價值。

**獨立測試**：只選擇狙擊者進入一場對局，切換八個瞄準方向，分別測試停止、移動、普攻、戰術配件與終極技能，即可驗證本故事。

**驗收情境**：

1. **給定** 玩家使用狙擊者且沒有移動或攻擊，**當** 玩家改變瞄準方向，**則** 角色顯示該方向的待機外觀。
2. **給定** 狙擊者正在移動，**當** 移動持續，**則** 角色循環播放目前面向的四格移動動畫。
3. **給定** 狙擊者成功施放普攻、戰術配件或終極技能，**當** 動作成立，**則** 角色播放目前面向的四格攻擊動畫。
4. **給定** 狙擊者同時移動與攻擊，**當** 攻擊動畫尚未完成，**則** 攻擊動畫優先；完成後依當下狀態回到移動或待機外觀。
5. **給定** 狙擊者面向上、左上或右上，**當** 玩家觀察角色，**則** 看見角色背面而不是朝下的正面。

---

### 使用者故事 2：不同畫面維持一致外觀（優先級：P2）

玩家在選角畫面、對局與玩家列表看到的狙擊者，會使用同一套偵察狙擊兵視覺身份，且不會遮住名稱、生命、狀態或操作提示。

**優先原因**：一致的選角預覽、對局角色與玩家列表圖示能降低玩家在不同畫面辨認角色的成本。

**獨立測試**：在選角頁查看狙擊者卡片，進入對局後查看角色與玩家列表，確認三處外觀一致且資訊文字可讀。

**驗收情境**：

1. **給定** 狙擊者卡片顯示，**當** 玩家瀏覽選角頁，**則** 卡片使用狙擊者的待機外觀。
2. **給定** 對局玩家列表包含狙擊者，**當** 列表顯示，**則** 使用縮小的狙擊者待機外觀，名稱與狀態文字仍完整可見。
3. **給定** 狙擊者在對局中存活，**當** 玩家觀察角色周圍，**則** 不會出現與角色身份無關的常駐底圈或外框；既有狀態標記仍可見。

---

### 使用者故事 3：素材異常時仍可遊玩（優先級：P2）

當狙擊者的個別圖片缺失、損壞或不符合透明背景要求時，玩家仍能正常選角與遊玩，角色改以既有幾何外觀顯示；其他角色與怪物不受影響。

**優先原因**：可替換的視覺素材不應讓遊戲中斷，也不應污染其他角色的既有顯示流程。

**獨立測試**：分別模擬一張狙擊者素材缺失、無法讀取、尺寸錯誤與不透明背景，再檢查選角、玩家列表與對局畫面。

**驗收情境**：

1. **給定** 狙擊者指定方向或動畫幀不可用，**當** 畫面需要繪製角色，**則** 使用既有幾何外觀且遊戲不中斷。
2. **給定** 狙擊者素材部分失效，**當** 玩家繼續移動或攻擊，**則** 角色仍可見且不會顯示空白或裁切圖片。
3. **給定** 其他角色或怪物出現在同一場對局，**當** 畫面更新，**則** 其既有外觀與行為維持不變。

### 邊界情況

- 瞄準向量為零、位於八方向分界角度或快速切換方向時，角色仍沿用穩定且可預期的面向；方向量化以 Pygame 螢幕座標 `angle = atan2(y, x)`（弧度）、右方為 0 度且順時針增加，使用 `floor((angle + pi / 8) / (pi / 4)) % 8`，正好落在 22.5 度分界時歸入順時針側的方向；零向量沿用前一個有效面向，初始面向為右。
- 狙擊者蓄力未完成、沒有彈藥或動作未成功時，不應誤播攻擊動畫。
- 攻擊與移動同時發生時，攻擊動畫必須優先，完成後恢復當下移動狀態。
- 玩家死亡與重生時保留既有死亡標記；重生後不得殘留上一條命的移動或攻擊畫面。
- 任一圖片出現棋盤格、白底、黑底、透明污染、空白、裁切或角色貼邊時，不得視為合格素材。
- 上方三個方向必須保持背面語意，不能因鏡像或錯向而顯示成正面。

## 需求

### 功能需求

- **FR-001**：本功能必須只替換狙擊者的角色外觀；破陣者、守衛者、追獵者、控場者、吸能者與三種怪物維持既有外觀。
- **FR-002**：狙擊者必須支援右、右下、下、左下、左、左上、上、右上八個面向。
- **FR-003**：每個面向必須提供一張待機圖片、四格移動動畫與四格攻擊動畫，共 72 張角色圖片。
- **FR-004**：狙擊者外觀必須呈現偵察狙擊兵身份：低矮細長輪廓、深藍／藍灰偽裝服、長槍、明確瞄具與青藍識別色；武器必須與角色手部保持連接且不可取代身體輪廓。
- **FR-005**：角色圖片必須使用一致的 Q 版像素畫法與俯視角；上、左上、右上方向必須呈現背面，不得使用文字、UI、logo、水印、場景、地面貼片、陰影、光環、煙霧或漂浮特效。
- **FR-006**：72 張來源圖片必須是 1024×1024 RGBA 畫布，四角透明、角色不貼邊或裁切，同一方向動畫幀的非透明內容中心偏移不得超過 16 個來源像素。
- **FR-007**：玩家停止移動且沒有成功攻擊或技能動作時，系統必須顯示目前面向的待機圖片。
- **FR-008**：玩家移動時，系統必須循環播放目前面向的四格移動動畫。
- **FR-009**：狙擊者成功執行普攻、戰術配件或終極技能時，系統必須播放目前面向的四格攻擊動畫；蓄力或失敗動作不得誤觸發攻擊動畫。
- **FR-010**：攻擊動畫必須優先於移動動畫；攻擊結束後必須依玩家當下狀態回到移動或待機外觀。
- **FR-011**：選角卡片、對局角色與玩家列表必須使用同一套狙擊者待機／動畫身份，並保留既有名稱、生命、狀態與操作資訊。
- **FR-012**：狙擊者圖片缺少、無法讀取、尺寸不一致、透明度不合格或僅部分動畫幀可用時，系統必須回退到既有幾何外觀且不得中斷遊戲。
- **FR-013**：本功能不得改變狙擊者或其他角色的傷害、碰撞、移動速度、蓄力、彈藥、技能效果、死亡重生、怪物行為或地圖規則。
- **FR-014**：狙擊者 72 張來源圖必須先以頭盔／面罩與角色身體核心的固定錨點統一角色本體比例，再以每個方向涵蓋 idle、move、attack 的身體核心聯合外框重新縮放整套圖片；武器外伸不得參與角色本體的縮放基準，完整角色與武器仍保留在 1024×1024 固定畫布內，同方向所有動畫幀共用相同比例。對局、選角與玩家列表載入時必須保留固定來源畫布，確保八個角度與走路幀的角色本體佔位大小一致，且朝上方向不得因垂直長槍外框放大。存活角色不得繪製常駐底圈，但死亡、護盾與控場等既有狀態標記必須保留。

### 關鍵實體

- **狙擊者外觀資產組**：由八個面向與待機、移動、攻擊三種視覺狀態組成，包含共 72 張圖片。
- **角色動畫狀態**：保存目前面向、移動狀態、移動動畫進度與攻擊動畫進度，供狙擊者在對局中保持連續且可預期的顯示。
- **外觀回退狀態**：代表指定狙擊者圖片不可用時，改用既有幾何角色外觀的顯示結果。

## 成功標準

### 可衡量成果

- **SC-001**（驗證 FR-002、FR-005）：狙擊者在八個指定方向皆能顯示正確面向，方向驗收通過率為 100%；上、左上、右上方向的正面錯置數為 0。
- **SC-002**（驗證 FR-003、FR-006）：72 張預定圖片達成 72/72 資產檢查通過：尺寸、透明四角、未貼邊、未裁切、動畫中心偏移與人工視覺檢查全部合格。
- **SC-003**：玩家可完整完成「選角 → 進入對局 → 八方向瞄準 → 移動 → 蓄力射擊 → 戰術配件／終極技能 → 死亡／重生」流程，過程中無因圖片問題造成的中斷或空白角色。
- **SC-004**：普攻、戰術配件與終極技能在成功施放時各自正確觸發攻擊動畫，成功率為 100%；未成功動作誤觸發次數為 0。
- **SC-005**：選角、對局與玩家列表中的狙擊者外觀身份一致，既有名稱、生命、狀態與操作資訊完整可讀。
- **SC-006**：連續遊玩 10 秒時，平均每秒至少 60 次畫面更新、任一單幀間隔不得超過 100 毫秒，且沒有閃爍、方向錯置、裁切或空白角色。
- **SC-007**（驗證 FR-012）：模擬任一單張狙擊者圖片失效時，下一次繪製即可使用幾何外觀回退並繼續操作；其他角色與怪物的外觀不變。
- **SC-008**（驗證 FR-014）：對局中的狙擊者每個方向與動畫幀都能在固定 50×50 顯示範圍內完整呈現，正常存活狀態不得出現常駐底圈，既有死亡／護盾／控場標記仍可辨識。

## 假設

- 使用 `sample.png` 只作為像素邊緣、比例與簡化節奏的畫法參考，不直接複製其背景、文字、道具或色彩。
- 狙擊者採偵察狙擊兵身份，使用深藍／藍灰主色與既有青藍狙擊者識別色；不新增另一套角色配色規則。
- 四格攻擊動畫同時供普攻、戰術配件與終極技能使用，不製作技能專用角色動作。
- 角色視覺更新不包含新的戰鬥特效、玩法規則、數值平衡、地圖、怪物或其他角色像素資產。
- 遊戲既有的方向控制、資訊層、死亡標記、選角流程與玩家列表均可沿用。
- 本功能不需要新增外部服務或第三方套件；現有 `pvpve_escape` 執行環境與測試方式沿用。
