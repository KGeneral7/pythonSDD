# 功能規格：PvPvE Escape 瀏覽器版

**功能分支**：`010-pvpve-escape-web`

**建立日期**：2026-08-29

**狀態**：Implemented；本機長時間效能量測與 owner production smoke test pending

**輸入**：使用者需求：將目前已發布的 `pvpve_escape` 桌面遊戲製作成完整對等的瀏覽器版本，新增獨立網頁資料夾並以私有網址發布，不改變既有桌面版。

## 背景與目標

本功能將目前已驗證的 PvPvE 中央撤離競技遊戲延伸到桌面瀏覽器，讓測試者不需要安裝桌面遊戲即可從私有網址開啟並遊玩。瀏覽器版以目前 `pvpve_escape` 的遊戲規則、角色、怪物、地形、瞄準、HUD、動畫與撤離流程為行為基準。

本功能新增一個獨立的網頁產品表面；既有 Python／Pygame 桌面版、`day1/`、`day2/` 與其他練習檔案不在本功能中重寫。

## 原版 1:1 還原基準（規範性）

「完整對等」以 `pvpve_escape/__main__.py` 啟動的 `main.py` 遊戲為唯一基準；不是只做相似的主題或功能清單。瀏覽器版必須在可玩的規則、更新順序、輸入、視覺層級與固定 UI 文字上逐項對齊。`pvpve_escape/map_editor.py` 是獨立桌面開發工具，不屬於遊戲本體。

- 邏輯畫面固定為 `1280×720`，世界為 `2400×1400`；桌面版的 120 FPS 目標、單次更新 `delta time` 上限 `0.05s`、單局 `240s`、撤離於 `210s` 開啟、撤離需求 `10s`、死亡重生 `5s` 與怪物重生 `6s` 必須保留。瀏覽器縮放只能等比例呈現這個邏輯表面。
- 每局固定建立 6 名玩家（玩家 0 為人類、玩家 1～5 為 dummy）、4 個營地、每營地 1 隻追獵獸／砲台蟲／重裝巨獸，共 12 隻怪物。玩家出生點為 `(300,180)`、`(1200,120)`、`(2230,170)`、`(170,1230)`、`(1200,1280)`、`(2230,1230)`；營地中心為 `(560,350)`、`(1840,350)`、`(560,1050)`、`(1840,1050)`。
- 原始地形配置的 18 個矩形不可合併或改位：正規化後必須得到 36 個厚牆格、22 個薄牆格、92 個草叢格，共 150 個有效地形格。厚牆阻擋且不可破壞；薄牆只按原版實際命中的路徑／範圍破壞；草叢依原版規則隱藏其他活玩家。
- dummy 只建立與重生、計時、受傷及可被測試工具放置／移回的狀態；原版 dummy 不自主移動、不自主攻擊。原版的角色被動欄位、終極技能地形互動與每個效果的生命周期不可用網頁版額外行為取代。
- Canvas 世界繪製順序、角色／怪物幾何、八方向角色素材、攻擊預覽、回看瞄準標記、頭頂資訊、右下玩家列表、死亡倒數、開發者提示與結果面板必須以原版 `rendering.py` 的固定邏輯座標與繁體中文文字為準；網頁版不得加入會改變原版資訊層級的現代化 HUD 面板、Toast 或額外撤離圖示。
- 首次開啟或重新整理時，角色／地圖資料尚未完成載入前必須顯示明確的 loading 頁；此期間不得顯示可開始遊戲的導覽／選角入口，也不得建立或更新比賽。載入完成（包含失敗資源已轉為 fallback）後才進入原版導覽流程。
- 網頁平台只允許一項必要適配：`Esc` 不關閉瀏覽器分頁，而是依規格返回導覽頁；其餘鍵鼠操作、`R`、`Tab`、`F1`、`1～5`、`M/N`、`Q/W/E` 與 Enter／Space 流程都必須保留。

## 使用者情境與測試

### 使用者故事 1 - 從私有網址進入並開始比賽（優先級：P1）

作為遊戲測試者，我想從私有網址開啟遊戲、閱讀玩法與操作提示、選擇角色及戰術配件，讓我能在瀏覽器開始一場完整的測試局。

**優先級理由**：這是所有瀏覽器遊戲行為的入口；若無法理解操作並開始比賽，其餘戰鬥與撤離功能都無法驗證。

**獨立測試**：開啟發布網址，從導覽頁進入選角頁，依序選擇六種角色與三種配件，開始一場比賽並確認六名玩家已建立。

**驗收情境**：

1. **假設**測試者第一次開啟私有網址且角色／地圖資料仍在載入，**當**頁面尚未完成載入，**那麼**會顯示 loading 頁，且不會顯示可開始入口、不會接受開始操作，也不會建立比賽。
2. **假設**測試者第一次開啟私有網址，**當**資料載入完成，**那麼**會顯示遊戲標題、勝利目標、主要操作與開始選擇的入口。
3. **假設**測試者位於導覽頁，**當**選擇開始，**那麼**會進入角色／戰術配件選擇頁。
4. **假設**測試者已選擇角色與配件，**當**開始比賽，**那麼**會建立一場包含一名人類玩家與五名固定假玩家的自由混戰。
5. **假設**測試者重新載入頁面，**當**遊戲再次啟動，**那麼**不會沿用上一局的生命、能量、強化、彈藥、地形或撤離狀態。

### 使用者故事 2 - 在瀏覽器中探索地圖並進行完整戰鬥（優先級：P1）

作為人類玩家，我想用鍵盤與滑鼠移動、瞄準並使用六種角色的專屬攻擊，讓我能在瀏覽器體驗與桌面版一致的 PvPvE 戰鬥循環。

**優先級理由**：角色差異、怪物威脅與玩家交戰是遊戲的主要玩法，也是「完整對等版」的核心價值。

**獨立測試**：開始比賽後，分別選擇六種角色，完成普攻、被動、大招與三種配件的操作，確認攻擊效果、冷卻、傷害與能量行為符合目前遊戲規則。

**驗收情境**：

1. **假設**比賽正在進行，**當**測試者使用 WASD 移動與滑鼠瞄準，**那麼**人類玩家會在地圖邊界內移動，鏡頭會跟隨且不顯示有效地圖以外的區域。
2. **假設**測試者選擇任一角色，**當**使用普攻，**那麼**會產生該角色獨有的攻擊形狀、飛行物或持續效果，並依規則消耗彈藥。
3. **假設**玩家對怪物或其他玩家造成有效傷害，**當**傷害成立，**那麼**會累積大招能量；能量充滿後使用大招會立即生效並歸零。
4. **假設**玩家已取得怪物擊殺強化，**當**繼續造成傷害，**那麼**攻擊與生命成長會依層數生效，且最多不超過十層。
5. **假設**測試者按住左鍵使用蓄力或持續型攻擊，**當**放開按鍵、失去焦點或玩家死亡，**那麼**蓄力與持續效果會正確結束，不會卡住或在背景中繼續攻擊。

### 使用者故事 3 - 讀懂敵人、地形與自身戰鬥狀態（優先級：P1）

作為需要做出戰鬥決策的玩家，我想辨認三種怪物、看到自己的完整資源與其他玩家的公開狀態，並利用牆體、草叢與自動瞄準提示，讓我能理解戰場資訊而不是只看到不可解釋的數值變化。

**優先級理由**：資訊可讀性與地形互動直接影響戰鬥公平性；這些內容也是目前 002～009 功能整合後的已發布行為。

**獨立測試**：在同一場比賽中觀察三種怪物、穿越與破壞地形、切換自動瞄準，並讓玩家受傷、補彈、恢復、死亡及重生，確認畫面資訊與狀態一致。

**驗收情境**：

1. **假設**地圖中存在怪物營地，**當**玩家觀察或接近怪物，**那麼**能辨認追獵獸、砲台蟲與重裝巨獸的不同定位、生命與攻擊行為。
2. **假設**玩家經過薄牆、厚牆或草叢，**當**移動、攻擊或使用適用技能，**那麼**阻擋、破壞與草叢可見資訊效果會依地形類型正確發生。
3. **假設**自動瞄準已開啟，**當**玩家在有效角度內瞄準目標，**那麼**畫面會顯示回看位置與瞄準預覽；投射物離手後不會持續追蹤目標。
4. **假設**玩家自己的生命、彈藥、配件、能量或強化改變，**當**畫面更新，**那麼**自己的頭頂資訊會同步更新；其他玩家只顯示允許公開的身份與生命資訊。
5. **假設**玩家離開戰鬥一段時間，**當**達到恢復條件，**那麼**生命會依規則恢復；受傷、死亡與重生期間的狀態提示都保持可辨識。

### 使用者故事 4 - 在中央撤離區爭取勝利（優先級：P1）

作為人類玩家，我想在最後階段前往中央撤離區，與其他玩家競爭個人停留進度，讓我能透過戰鬥、走位與技能控制爭取唯一勝利。

**優先級理由**：撤離是整場比賽的最終目標，能驗證前期發育、PvP、地形與生存狀態是否正確串接。

**獨立測試**：使用開發者測試功能將假玩家放入撤離區，驗證單人進度、多人同區、離場個別歸零、同幀裁決、死亡清除與時間到無人勝利。

**驗收情境**：

1. **假設**比賽進入最後三十秒，**當**玩家進入中央撤離區，**那麼**該玩家開始累積自己的撤離進度。
2. **假設**玩家持續在撤離區內停留十秒，**當**進度達到要求，**那麼**比賽立即結束並公布該玩家為勝者。
3. **假設**兩名以上玩家同時位於撤離區，**當**畫面更新，**那麼**每名仍在區域內的玩家都會繼續累積自己的進度，不會互相阻塞。
4. **假設**玩家離開撤離區或在區域內死亡，**當**狀態更新，**那麼**只有該玩家的進度歸零，其他玩家進度不受影響。
5. **假設**同一更新週期有多名玩家完成撤離，**當**勝負裁決，**那麼**會依固定玩家識別順序選出唯一勝者；若四分鐘結束仍無人完成，會顯示無人勝利。
6. **假設**比賽已結束，**當**測試者選擇重新開始或按下瀏覽器版的返回操作，**那麼**會停止上一局更新並回到可重新選擇的畫面。

### 使用者故事 5 - 在不同桌面瀏覽器尺寸中穩定使用（優先級：P2）

作為遊戲測試者，我想在常見桌面瀏覽器視窗尺寸中讀取介面並操作遊戲，讓發布網址不只在單一固定視窗才可用。

**優先級理由**：網頁版需要適應瀏覽器視窗，但仍以目前桌面鍵盤／滑鼠遊玩方式為主要目標。

**獨立測試**：以 1280×720、1024×576 與較寬的桌面視窗開啟遊戲，完成選角、移動、攻擊與結果流程，確認畫面不裁切且滑鼠座標一致。

**驗收情境**：

1. **假設**瀏覽器視窗比例不同於遊戲邏輯畫面，**當**視窗縮放，**那麼**遊戲畫面維持等比例，主要資訊與操作提示仍可讀。
2. **假設**角色或地圖素材載入失敗，**當**遊戲繼續啟動或進行，**那麼**會使用可辨識的回退外觀，不阻止玩家遊玩或改變規則狀態。
3. **假設**測試者把瀏覽器分頁切到背景再返回，**當**遊戲恢復更新，**那麼**不會因累積過大的時間差讓玩家、怪物或投射物瞬間穿越邊界。

### 邊界情況

- 瀏覽器首次載入或重新整理時，素材尚未完成載入前必須顯示 loading 頁且不得開始遊戲；暫時無法載入部分素材時，完成載入嘗試後仍須提供可辨識的導覽、選角與回退外觀。
- 瀏覽器視窗縮放、裝置像素比例或滑鼠位於畫布外時，瞄準座標不得偏移到錯誤的世界位置。
- 瀏覽器失去焦點時，持續攻擊、蓄力、光束與按鍵狀態必須停止或安全清除，不能在重新聚焦後誤觸發。
- 玩家不得移出世界邊界；鏡頭在世界邊緣時不得顯示地圖外的有效遊戲區域。
- 投射物遇到厚牆、薄牆、草叢或世界邊界時，必須依各自的地形互動規則停止、破壞或穿越。
- 只應破壞實際命中的單一地形格；相鄰未命中格不得被連帶改變。
- 自動瞄準只在施放當下解析一次；目標改變位置、轉向或離開有效角度後，投射物不得自動修正路徑。
- 玩家死亡時必須清除強化、大招能量、撤離進度與不應保留的持續技能；五秒後安全重生且不得直接淘汰。
- 怪物死亡後須在原生成區等待六秒重生；怪物的最後有效傷害來源必須決定強化歸屬。
- 撤離區只在剩餘三十秒啟用；撤離勝利在時間到的同一更新週期中優先於無人勝利。
- 同一更新週期有多名玩家達標時，勝者不得依賴不穩定的處理順序。
- `R` 重新開始與重新載入頁面都必須建立全新的比賽狀態，不得殘留上一局資料。
- 瀏覽器版以桌面鍵盤／滑鼠為目標，不提供觸控操作、線上多人、帳號或跨裝置同步。

## 需求

### 功能需求

- **FR-001**：系統必須能由 Sites 私有發布網址開啟；Sites 的私有存取控制必須拒絕未被授權的公開訪客，遊戲本身不另建帳號或登入驗證。
- **FR-002**：系統必須在開始前提供玩法目標、主要操作、角色差異、怪物定位與撤離規則的可讀提示。
- **FR-003**：系統必須提供六種角色與三種戰術配件（短距離衝刺、短時間護盾、範圍控場）的選擇，並清楚顯示目前選取項目。
- **FR-004**：系統必須建立六個獨立玩家狀態，包含一名人類玩家與五名固定假玩家，且不得建立固定隊伍。
- **FR-005**：人類玩家選定的角色與配件必須套用於玩家 0；五名假玩家必須使用其餘五種不同角色並各自攜帶有效配件。
- **FR-006**：六種角色必須各自擁有不同的普攻、被動能力與大招：破陣者、狙擊者、守衛者、追獵者、控場者與吸能者。
- **FR-007**：角色普攻必須遵循目前已驗證的攻擊形態，包括扇形散射、蓄力直線、弧形盾擊、往返回旋飛刃、重力地雷與持續吸能光束。
- **FR-008**：每種角色的彈匣容量必須介於 2 至 4 發，總彈藥無限；彈藥消耗後必須依角色設定自動恢復，恢復間隔介於 0.2 至 0.8 秒。
- **FR-009**：玩家對怪物或其他玩家造成有效傷害時必須累積大招能量；能量上限為 100，使用大招後必須歸零。
- **FR-010**：怪物擊殺必須將最後有效傷害歸屬給最後一名造成有效傷害的玩家，並只給該玩家一層強化；強化最多十層，每層使攻擊與生命上限增加 3%。
- **FR-011**：系統必須提供四個怪物生成區，每個生成區包含追獵獸、砲台蟲與重裝巨獸，並維持三種怪物可辨識的生命、速度、攻擊與距離定位。
- **FR-012**：怪物必須支援營地遊蕩、看見玩家後追擊或保持攻擊距離、被阻擋時繞行，以及死亡後於原生成區等待六秒重生。
- **FR-013**：玩家必須能使用 WASD 移動、滑鼠瞄準、滑鼠左鍵普攻、滑鼠右鍵大招與 Space 戰術配件；按鍵提示必須與實際操作一致。
- **FR-014**：系統必須提供預設開啟的輕度自動瞄準；`Tab` 必須能切換自動瞄準，自動瞄準只在施放當下使用 0.20 秒前的位置、有效角度內的最近目標，投射物離手後不得追蹤。
- **FR-015**：系統必須顯示與目前攻擊形態一致的瞄準線、範圍、飛行路徑、回看位置與命中回饋，且不得把僅供畫面的效果誤算為規則傷害。
- **FR-016**：地圖必須提供厚牆、可破壞薄牆與草叢；厚牆阻擋，薄牆可依攻擊或衝刺規則破壞，草叢必須影響其他玩家的可見資訊。
- **FR-017**：破壞地形時系統只能更新實際命中的地形格；建立新比賽時所有地形格必須恢復初始狀態。
- **FR-018**：玩家必須在世界邊界內移動；鏡頭跟隨人類玩家時必須限制在有效世界範圍內。
- **FR-019**：人類玩家頭頂必須顯示身份、角色、生命、彈藥、配件就緒圓點、能量與強化；其他玩家只可顯示身份與生命等公開資訊，不得洩漏私人戰鬥資源。
- **FR-020**：玩家生命值低於上限且離開戰鬥達到五秒後，必須依目前規則恢復生命；生命條、數值、狀態與死亡倒數必須同步更新。
- **FR-021**：玩家生命值降至零時，系統必須清除該玩家的強化、大招能量、撤離進度與不應延續的持續效果；死亡五秒後須於安全外圍位置重生並可重新遊玩。
- **FR-022**：單局時間必須限制為四分鐘；中央撤離區必須在剩餘三十秒啟用，個別玩家連續停留十秒即可完成撤離。
- **FR-023**：多人同時位於撤離區時，每名玩家的個人進度必須獨立累積；離開或死亡只重置該玩家進度，不得影響其他玩家。
- **FR-024**：第一名完成撤離的玩家必須立即獲勝；同一更新週期多人完成時必須依固定玩家識別順序裁決；四分鐘結束前無人完成時必須顯示無人勝利。
- **FR-025**：系統必須提供開發者測試模式，可用 F1 開關、數字鍵 1～5 選取假玩家、M 放入中央撤離區、N 返回出生點，且測試控制不得改寫一般撤離規則。
- **FR-026**：系統必須提供導覽、選角、進行中、死亡／重生、勝利、無人勝利與重新開始等可辨識狀態；比賽結束後不得繼續更新上一局。
- **FR-027**：瀏覽器視窗縮放時，遊戲主要畫面、HUD、角色、地圖與操作提示必須維持可讀的等比例呈現，滑鼠座標必須正確轉換。
- **FR-028**：角色與地圖素材載入失敗時，系統必須使用可辨識的回退外觀；素材問題不得造成頁面崩潰、改變規則或阻止重新開始。初始載入期間可等待所有資源載入嘗試完成，但完成後必須能進入導覽並遊玩。
- **FR-029**：瀏覽器版的遊戲狀態只保存在目前頁面期間；重新載入或重新開始不得保留生命、彈藥、能量、強化、地形與撤離資料。
- **FR-030**：本功能不包含線上連線、伺服器同步、帳號系統、持久化戰績、觸控控制或桌面地圖編輯器。
- **FR-031**：網站必須以私有方式發布，完成發布後提供可由擁有者開啟的 production URL。
- **FR-032**：瀏覽器版必須以 `1280×720` 邏輯表面呈現原版 intro、選角、對局 HUD、開發者提示與結果面板；縮放只能等比例 contain，不得以額外的 header、footer、現代化資訊卡、Toast 或撤離圓環取代原版畫面層級。
- **FR-033**：瀏覽器版必須保留原版 18 個地形矩形及其位置、尺寸、順序與類型；建立一局後正規化結果必須為 36 個厚牆格、22 個薄牆格、92 個草叢格，且四營地與六個玩家出生點必須使用原版座標。
- **FR-034**：瀏覽器版每次更新必須遵循原版玩家／效果／怪物／投射物／回復／撤離／結果順序；五名 dummy 不得自行移動或攻擊，但其計時、受傷、死亡、重生與開發者測試放置行為必須保留。
- **FR-035**：六種角色的被動定義、攻擊動作預設地形互動、投射物／持續效果生命周期與視覺繪製必須逐項對應 `characters.py`、`world.py` 與 `rendering.py`；未明確由原版授權的薄牆破壞不得新增。
- **FR-036**：原版固定繁體中文 UI 文案與其固定座標區域必須存在於導覽、選角、對局 HUD、開發者模式與結果狀態；可及性語意可額外存在，但不得以可見網頁資訊改變原版內容。
- **FR-037**：系統必須在初始資料載入期間顯示 loading 頁，並在所有必要地圖／角色資源完成載入或轉為 fallback 前阻止導覽、選角、比賽建立與比賽更新；載入完成後才可進入 `intro`，且 loading gate 不得建立額外的 `MatchState`。

### 關鍵實體

- **瀏覽器遊戲**：可由私有網址開啟的單局遊戲表面，保存目前畫面階段與遊戲狀態。
- **比賽**：保存單局時間、玩家、怪物、地形、撤離區、效果與勝負結果。
- **玩家**：代表人類玩家或假玩家，包含身份、角色、配件、位置、生命、彈藥、能量、強化、狀態、瞄準與撤離進度。
- **角色**：代表六種戰鬥定位，包含普攻、被動、大招、彈匣與移動等設定。
- **戰術配件**：代表位移、防禦或控場工具，包含效果與冷卻狀態。
- **怪物**：代表追獵獸、砲台蟲或重裝巨獸，包含生成區、行為、生命、攻擊、導航與重生狀態。
- **地形格**：代表厚牆、薄牆或草叢的單一地圖單位，保存位置、類型與本局是否仍有效。
- **戰鬥動作與效果**：代表攻擊、投射物、光束、護盾、擊退、減速、定身、治療與命中回饋。
- **輸入狀態**：代表當前一幀的移動、瞄準、按下、長按、放開、焦點與開發者測試操作。
- **資源載入狀態**：代表地圖／角色資源是否已完成載入嘗試、已解析資源與 fallback 失敗計數；載入完成前不建立比賽。
- **發布網址**：供擁有者開啟網頁版的私有 production URL。

## 成功標準

### 可衡量成果

- **SC-001**：測試者能從私有發布網址在一次資源載入完成後看到玩法導覽，且載入期間只看到 loading 頁、不建立比賽、不接受開始操作，並在一分鐘內進入角色／配件選擇頁。
- **SC-002**：測試者可各使用六種角色與三種配件開始比賽，六次開始都建立正確的六名玩家狀態且沒有阻塞性錯誤。
- **SC-003**：六種角色的普攻、被動、大招、彈藥消耗、能量累積與三種配件效果，均能在獨立測試情境中觀察到正確且彼此不同的結果。
- **SC-004**：在至少 20 個可重複的 deterministic 邊界／回歸案例中，玩家、怪物、投射物、地形碰撞、薄牆／草叢破壞、視線與鏡頭結果都符合目前已驗證的遊戲規則。
- **SC-005**：在至少 20 個可重複的 deterministic 狀態案例中，彈藥、生命恢復、能量、強化、死亡清除、五秒重生與配件就緒狀態顯示都與實際狀態一致。
- **SC-006**：在至少 20 個可重複的 deterministic 撤離邊界案例中，多人同區進度、個別離場歸零、死亡歸零、同幀裁決、撤離優先與時間到無人勝利結果都可重現。
- **SC-007**：以 1280×720、1024×576 與較寬的桌面瀏覽器視窗完成主要流程時，主要畫面、HUD、選角資訊與結果提示均不被裁切且滑鼠瞄準位置正確。
- **SC-008**：在記錄瀏覽器版本、作業系統、viewport 與硬體的固定桌面測試環境中，以內建 frame sampler 連續量測正常遊玩至少 60 秒，平均更新率必須至少 55 FPS，且不因角色或地圖素材逐幀重新載入而出現明顯卡頓。
- **SC-009**：任一角色或地圖素材載入失敗時，100% 的測試情境仍能進入比賽、繼續更新規則並重新開始，且使用者能辨認回退外觀。
- **SC-010**：比賽結束、按下重新開始或重新載入頁面後，100% 的測試情境都不會殘留上一局的生命、能量、強化、地形、彈藥或撤離狀態。
- **SC-011**：私有 Sites 發布成功後，已授權擁有者能開啟 production URL 完成導覽、選角與至少一個可玩戰鬥情境；以未授權瀏覽器 session 開啟同一 URL 時不得取得網站內容。
- **SC-012**：以固定 seed 比對原版與瀏覽器版的初始 roster、出生點、營地、150 個正規化地形格、dummy 靜止狀態、角色動作種類與終極技能地形互動，所有 parity fixture 均必須一致。
- **SC-013**：在 `1280×720` 邏輯座標逐項檢查導覽、選角、HUD、開發者提示與結果面板時，原版固定文字、主要座標區域與繪製層級均存在，且不可見的瀏覽器可及性輔助不改變可見畫面。
- **SC-014**：在資料載入尚未完成的測試情境中，100% 不會顯示可開始的遊戲畫面、不會建立 `MatchState` 或推進遊戲時間；資源成功或 fallback 完成後才會顯示導覽並可依既有流程開始。

## 假設

- 瀏覽器版以目前 `pvpve_escape` 已發布的桌面行為為基準；若舊 SDD 文件與最新程式行為有差異，差異會在後續研究與計畫文件中記錄，並以最新已驗證行為為準。
- 目標使用者是使用桌面瀏覽器、鍵盤與滑鼠的遊戲測試者；手機與觸控操作不屬於本功能。
- 瀏覽器版仍是單機測試版，由一名人類玩家操作，搭配五名固定假玩家；不提供真正線上多人。
- 遊戲狀態只存在目前頁面記憶體中，不保存帳號、戰績、設定、地圖破壞或跨裝置進度。
- 現有角色與地圖 PNG 素材可作為瀏覽器版的視覺基礎；破陣者與狙擊者保留八方向的待機、移動與攻擊身份，其餘角色保留可辨識的幾何外觀。
- 素材、字型或瀏覽器能力異常時，遊戲優先維持可玩與可辨識，不以素材失敗改寫戰鬥規則。
- loading 頁是 `GameState` 之外的短暫資源閘門；資源完成前不接受導覽／選角快捷鍵、不建立比賽，完成後才進入既有 `ScreenPhase` 四值流程。
- `Esc` 在瀏覽器版不關閉瀏覽器分頁；在 playing／result 畫面返回 intro 導覽，result 的「再玩一次」或回選角按鈕才進入角色／戰術選擇；`R` 在任何畫面清除目前比賽／選擇並回到角色／戰術選擇頁；`Tab` 只切換自動瞄準，不切換 HUD 私有資料。
- 私有 URL 的授權邊界由 Sites hosting 提供；瀏覽器遊戲不保存或驗證帳號、session 或權限資料。
- `map_editor.py` 是桌面開發工具，不納入瀏覽器遊戲本體。
- 發布目標是私有 Sites production URL；本功能不新增自訂網域或公開分享權限。
- 100% 還原不代表瀏覽器可執行 Pygame；它代表以上述原版基準建立 deterministic parity fixture，並讓 Canvas／DOM 的可見畫面與原版固定邏輯座標一致。
