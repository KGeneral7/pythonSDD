# 研究紀錄：玩家頭頂 HUD 與個人戰鬥資訊

**功能識別字**：`006-overhead-player-hud`
**研究日期**：2026-08-27
**狀態**：已完成；規格中的行為與技術選擇沒有待釐清項目

## 目前架構摘要

`pvpve_escape` 是以 Python 3.11 與 Pygame 建立的單機 PvPvE 桌面遊戲。遊戲已經在 `rendering.py` 的 `draw_match()` 中依序繪製世界與 HUD；`draw_world()` 每一幀把玩家世界座標轉成螢幕座標，並呼叫玩家覆蓋資訊繪製函式。固定在螢幕左上角的玩家戰鬥面板則集中在 `draw_hud()`；玩家死亡與配件冷卻生命週期則由 `rules.py` 的既有玩家生命週期函式處理。

`PlayerState` 已包含本功能需要的來源狀態：玩家編號、角色、生命、彈藥、配件冷卻、大招能量、強化層數與死亡計時。因此本功能不需要新增持久化資料或狀態欄位；除了已確認的配件冷卻死亡生命週期外，主要是既有狀態的顯示層重組。

## 決策 1：沿用現有世界座標轉換與玩家覆蓋繪製流程

**決定**：在 `rendering.py` 擴充既有 `_draw_player_overlay()`，由 `draw_world()` 以每個玩家當幀的螢幕座標繪製完整或精簡資訊；移除 `draw_hud()` 內的固定玩家戰鬥面板。

**理由**：

- 玩家位置與鏡頭轉換已在同一條渲染路徑完成，資訊自然會跟隨玩家移動與鏡頭移動。
- 不需要在 `world.py`、`controllers.py` 或遊戲主迴圈新增另一套同步機制。
- 可保留右上角撤離/倒數、底部移動/Tab/F1 等非攻擊控制提示、玩家名單與開發者資訊等全域 UI；普攻、大招與配件按鍵提示只留在選角頁。

**替代方案**：建立獨立 HUD 場景或將覆蓋資訊掛到 Pygame Sprite 群組。這會重複既有座標與繪製邏輯，且沒有為目前的單機渲染模型帶來必要價值，故不採用。

## 決策 2：以目前單機觀察者規則判斷私有資訊

**決定**：沿用既有渲染函式的 `viewer_id`（目前預設為 0），以 `player.player_id == viewer_id` 判定目前本機玩家。所有可見玩家都繪製玩家編號/名稱與生命資訊；只有觀察者自己的玩家顯示彈藥、配件、大招與強化等私有資訊。

**理由**：

- `world.create_match()` 已將編號 0 建立為人類玩家，其餘為目前的 dummy 玩家，而 `draw_world()`/`draw_hud()` 已有 `viewer_id=0` 參數。
- 不需要在 `MatchState` 再新增 viewer 欄位；將既有參數傳入覆蓋層即可完成目前需求。
- 這個決策保留未來多人化的擴充點：若日後改變觀察者 ID，只需傳入新的 `viewer_id`，不必改變顯示契約。

**替代方案**：在 `MatchState` 新增 `viewer_player_id`。目前只有單一本機玩家且沒有網路同步需求，這會是未被使用的狀態欄位，故不採用。

## 決策 3：使用文字、分段彈藥與圓形配件指示器

**決定**：

- 生命保留既有生命條與數值，所有玩家都顯示。
- 彈藥以最多 `ammo_capacity` 個短分段/圓點表示，已用彈藥以既有 accent 色顯示，空彈藥以低對比色顯示，並保留目前數值文字以確保可讀性。
- 配件用單一圓圈表示；可使用時使用既有藍色 `EXTRACTION_COLOR`，冷卻或死亡時使用既有灰色 `PANEL_BORDER_COLOR` 或同等 muted 色。
- 大招以 `0%` 至 `100%` 的整數百分比文字顯示。
- 強化以 `Upgrade`/`強化` 與目前層數顯示。

**理由**：這些元件都可由現有 Pygame primitive 與字型繪製，符合專案不新增資產/套件的約束，也能在玩家頭上形成緊湊的一到兩行資訊帶。

**替代方案**：加入圖示圖片或第三方字型。這會引入資產載入、解析度與額外相依性問題，與本次需求的核心「位置、可見範圍與狀態同步」無關，故不採用。

## 決策 4：從既有角色資料推導選角頁攻擊提示

**決定**：在 `draw_selection()` 的角色卡片中呈現攻擊種類、傷害、距離/射程、攻擊速度與可辨識的操作提示；特殊角色提示直接由既有 `primary_kind` 與 `character_id` 推導，不新增角色模型欄位。配件與大招仍由選角頁既有卡片提供其基本名稱/說明，戰鬥中的即時資源則只放在玩家頭上。

**理由**：角色定義已包含角色定位與攻擊參數，選角頁已經繪製部分數值，只需補齊提示內容即可。提示在戰鬥中不再佔用固定左上角面板。

**替代方案**：建立另一個角色提示設定表。這會與 `characters.py` 的既有資料形成重複來源，增加角色新增或調整時不一致的風險，故不採用。

## 決策 5：保持既有渲染與遊戲流程介面

**決定**：保留 `draw_match(surface, match)`、`draw_world()`、`draw_hud()` 的公開呼叫方式與控制器綁定；不改變移動、攻擊、彈藥恢復、大招計算或升級規則。配件冷卻採已確認的死亡生命週期：死亡不重置目前值、死亡期間凍結，重生後才繼續倒數。`draw_hud()` 只繼續承載全域資訊與本機死亡中央倒數，底部固定列不再呈現普攻、大招或配件按鍵提示。

**理由**：本功能的風險集中在 UI 可見性與定位。縮小變更面可避免破壞既有碰撞、戰鬥與遊戲流程，並讓既有測試能以最小幅度更新。

## 決策 6：本機死亡時顯示中央重生倒數

**決定**：在 `draw_hud()` 取得目前 `viewer_id` 對應玩家；只有該玩家死亡且 `death_timer` 大於 0 時，使用既有 `draw_text()` 與 Pygame 字型在視窗中心繪製大型倒數文字。其他玩家死亡不觸發本機中央倒數，倒數結束或玩家重生後立即停止繪製。

**理由**：死亡倒數是本機玩家需要知道的流程狀態，不屬於其他玩家可見資訊；沿用現有字型快取與 HUD 繪製順序即可加入，不需要新增 UI 框架或狀態欄位。

## 決策 7：以單元測試加手動遊玩驗證顯示契約

**決定**：在既有 `pvpve_escape/tests/test_rendering.py` 增加無視窗/最小 Pygame 測試，至少以 20 次迴圈驗證玩家座標/鏡頭變更與邊界狀態，並驗證公開與私有資訊的繪製分支、配件顏色、死亡狀態與選角按鍵提示；再以完整 unittest、compileall 與短流程手動遊玩驗證。

**理由**：像素位置與可見內容適合用可控的繪製呼叫與狀態斷言驗證，實際字型排版與重疊則需由遊戲視窗人工確認。此方式符合憲章要求的「可重現自動測試 + 每個可見行為的手動驗證」。

## 決策 8：在玩家螢幕錨點離開 viewport 時剔除其他玩家 HUD

**決定**：`draw_world()` 在完成 `_screen_point()` 後，對 `player.player_id != viewer_id` 的玩家檢查該錨點是否落在目前 `surface.get_rect()` 內；若不在，跳過該玩家的頭頂 overlay 呼叫，保留既有角色圖形與 Pygame viewport 裁切。錨點回到 viewport 內時，由下一幀重新繪製公開資訊。

**理由**：頭頂 overlay 的邊界夾取是為了讓仍在畫面內、靠近邊緣的玩家保持可讀，不能同時被用來表示離屏玩家；否則玩家離開視野後，血量條會被夾到畫面邊緣而產生殘留。將判定放在 `draw_world()` 的玩家迴圈，也能保留既有地形/灌木可見性規則，並確保本機玩家的「隨時顯示」契約不受其他玩家剔除影響。

**替代方案**：在玩家迴圈入口整組剔除離屏玩家。這雖然也能移除頭頂資訊，但會改變角色中心剛離開 viewport 時既有的 Pygame 裁切行為；只跳過 overlay 可將修正限制在血量條殘留問題，故不採用整組剔除。

## 風險與處理

| 風險 | 處理方式 |
|---|---|
| 頭頂資訊在螢幕邊緣被裁切或離屏後殘留 | 對仍在 viewport 內的錨點做有限的水平/垂直夾取；其他玩家錨點完全離開 viewport 時，在 `draw_world()` 跳過其 overlay 呼叫，回到 viewport 後由當幀重新繪製。 |
| 六名玩家靠近時資訊重疊 | 每個資訊區塊固定以玩家中心為基準，最大寬度 240 像素、左右至少 8 像素邊界；超長身份文字省略，不以搬到螢幕角落解決重疊；只處理顯示層，不改變角色位置。 |
| 私有資訊意外洩漏到其他玩家 | 將 `show_private_info` 判定集中於覆蓋資訊繪製入口，並以不同狀態的其他玩家做測試；viewport 剔除只針對其他玩家，不改變本機玩家的顯示例外。 |
| 既有測試依賴左上面板文字 | 更新測試的預期為新契約，並確認全域倒數、撤離、名單、開發者資訊與本機死亡倒數仍存在。 |
| 死亡時配件冷卻被錯誤重置或倒數 | 將冷卻保留與凍結規則集中在 `rules.py` 的死亡／重生／計時函式，並以死亡等待與重生後倒數測試保護生命週期。 |

## 結論

本功能不需要新的外部套件、網路介面、資料庫或新的遊戲狀態欄位。實作集中於既有 `rendering.py`、`rules.py` 與相關測試；規格、計畫與任務已完成，並已依人工驗收結果補入中央死亡倒數及配件冷卻死亡生命週期的文件追蹤；本次追加的 viewport 剔除則保護其他玩家離屏後不殘留頭頂血量條。完整驗證後已由 [PR #10](https://github.com/KGeneral7/pythonSDD/pull/10) 合併，並發布 [v0.3.1](https://github.com/KGeneral7/pythonSDD/releases/tag/v0.3.1)。
