# UI 契約：玩家頭頂 HUD 與個人戰鬥資訊

此契約描述 `pvpve_escape` 在選角頁、戰鬥畫面與結果流程中的可觀察 UI 行為。它不是網路 API；其目的在於讓渲染實作與測試對同一組可見性、位置與顏色規則保持一致。

## 戰鬥中的頭頂覆蓋層

### 公開資訊

每一名仍在世界中可見的玩家，在其角色上方顯示：

1. 玩家編號與角色名稱。
2. 生命條。
3. 目前生命值/最大生命值。

公開資訊適用於本機玩家與其他玩家。生命條在受傷、治療、死亡或復活後，於下一次畫面更新同步。

### 本機私有資訊

只有目前觀察者自己的玩家（目前 `viewer_id=0`，即 `player.player_id == viewer_id`）在自己的公開資訊下方顯示：

| 元件 | 顯示契約 |
|---|---|
| 彈藥 | 目前彈藥數值，加上不超過容量的分段指示；空彈藥仍保留可辨識的低對比分段 |
| 配件 | 一個圓圈；可使用為藍色，冷卻中或死亡為灰色 |
| 大招 | `0%`–`100%` 的整數百分比 |
| 強化 | 目前強化層數，使用既有角色/升級語意 |

其他玩家的頭頂覆蓋層不得繪製上述四類元件，也不得以數值、顏色、圖示、tooltip 或死亡倒數的形式間接洩漏。

## 本機死亡中央倒數

目前觀看者自己的玩家死亡且 `death_timer > 0` 時，戰鬥 HUD 必須使用既有 Pygame 字型以大型文字在螢幕正中央顯示剩餘死亡時間，並於每次畫面更新同步。玩家存活、倒數結束或觀看其他玩家死亡時，不顯示此中央倒數；其他玩家不得從本機畫面取得對方的死亡倒數。

## 位置與移動契約

- 覆蓋層的基準點來自該玩家的世界座標經目前鏡頭轉換後的螢幕座標。
- 每幀都要由最新的玩家位置與鏡頭位置重新計算；玩家移動、鏡頭追蹤或鏡頭移動後，資訊仍跟著相同玩家。
- 覆蓋層應位於角色頭部上方，生命條、識別列與本機私有列採固定的垂直順序，不得回到螢幕左上角作為玩家狀態面板。
- 頭頂資訊區塊最大寬度為 240 像素，左右至少保留 8 像素視窗邊界；超長身份文字以省略號截斷。
- 靠近視窗邊界時只可在當幀對整個資訊區塊做有限夾取，且仍須維持與所屬玩家的關聯；不可把資訊固定成全域 UI。
- 多名玩家靠近時，每個資訊區塊保留自己的玩家中心基準與固定垂直順序，不以搬到螢幕角落解決重疊，也不改變玩家碰撞或移動。

## 配件顏色契約

| 狀態 | 圓圈顏色 | 說明 |
|---|---|---|
| 存活且冷卻完成 | 既有藍色 `EXTRACTION_COLOR` | 可使用 |
| 存活且冷卻中 | 既有灰色 `PANEL_BORDER_COLOR` 或 muted 灰 | 不可使用 |
| 死亡 | 灰色 | 不得保留上一幀的藍色可用狀態 |

顏色只對本機玩家可見；其他玩家不顯示配件圓圈，因此不能從對方的圓圈顏色推知狀態。

## 固定 HUD 移除與保留範圍

戰鬥畫面左上角原本用來呈現本機玩家姓名、生命、攻擊數值、彈藥、能量、強化、死亡倒數與攻擊提示的固定玩家面板應移除。

仍保留既有且不屬於本次玩家私有資訊重定位的全域 UI，例如：

- 右上角倒數、撤離狀態與相關提示。
- 底部移動、Tab、自動瞄準或 F1 等非攻擊提示；不保留左鍵普攻、右鍵大招或 Space 配件提示。
- 玩家名單/存活名單。
- 開發者或除錯覆蓋層（若目前設定開啟）。

移除固定玩家面板與底部攻擊提示不得改變輸入綁定、戰鬥更新、撤離勝負條件或任何傷害與資源規則。

## 選角頁攻擊提示契約

選角頁的角色卡片應在玩家選擇前提供足以理解主要攻擊的提示，至少包含：

- 主要攻擊種類或定位。
- 傷害/傷害型態。
- 射程或作用距離。
- 攻擊速度、冷卻或同等節奏資訊（若角色資料有提供）。
- 與目前控制器一致的攻擊操作提示。

狙擊型角色需清楚標示遠距離/狙擊定位；吸血或生命汲取型角色需清楚標示命中回血/汲取效果。提示應由既有角色定義推導，避免選角頁與實際戰鬥規則使用兩套資料。

選角頁不需要顯示某一場戰鬥的即時彈藥、配件冷卻、大招百分比或強化層數；這些只屬於戰鬥中的本機頭頂覆蓋層。

## 流程與錯誤行為

| 流程/狀態 | 預期行為 |
|---|---|
| 選角中 | 顯示攻擊相關角色提示；不顯示頭頂戰鬥資源 |
| 戰鬥中 | 顯示每名玩家的公開資訊；僅本機玩家追加私有資訊 |
| 本機玩家彈藥為 0 | 顯示 0 與空分段，不因 UI 而阻止既有恢復/攻擊規則 |
| 本機玩家大招未滿/已滿 | 顯示夾取後的百分比；未滿不顯示為可用，已滿仍不新增額外對外提示 |
| 本機玩家死亡 | 生命公開資訊照常顯示；私有配件圓圈為灰色，配件冷卻值保留且死亡期間凍結；中央顯示自己的死亡倒數 |
| 其他玩家死亡 | 只保留名稱/編號與生命資訊，不出現對方的任何資源列 |
| 比賽結束/結果頁 | 回到既有結果畫面，不把戰鬥頭頂覆蓋層帶入結果頁 |

## 驗證對應

測試至少應覆蓋：

1. 六名玩家的公開資訊皆存在，其他五名不含私有資訊。
2. 本機玩家的彈藥、配件、大招與強化在狀態變化後更新。
3. 配件可用/冷卻/死亡三種顏色狀態正確。
4. 至少 20 次玩家世界座標與鏡頭改變後，覆蓋層的繪製座標每次都同步改變。
5. 彈藥 0/滿額、大招 0/100、配件可用/冷卻/死亡與生命邊界各重複至少 20 次，顯示值與顏色都正確。
6. 選角頁包含一般、狙擊與汲取型角色的攻擊提示，且 Q/W/E 配件選擇仍可用。
7. 原本保留的全域 HUD 與完整遊戲流程仍可用。
8. 本機死亡倒數使用大型 Pygame 字型置中顯示，隨 `death_timer` 更新並在重生後消失；其他玩家死亡不會顯示該倒數。
9. 配件冷卻在死亡時不重置、死亡期間不倒數，重生後才繼續倒數。
