# 實作計畫：小怪動態尋路與營地遊蕩

**分支**：`codex/007-monster-navigation-wander` | **日期**：2026-08-28 | **規格**：[spec.md](./spec.md)

**輸入**：`specs/007-monster-navigation-wander/spec.md` 中的小怪繞牆、破牆後即時改道、營地警戒遊蕩、速度平衡與玩家 0 號出生距離需求。

## 摘要

目前 `pvpve_escape/world.py` 讓小怪直接朝玩家移動；遇到斜向牆角時，既有碰撞函式會把位置停在第一個接觸點，下一幀又重複相同方向，因此可能長時間卡在牆前。本功能會新增不依賴畫面的 40px 網格 A* 尋路模組，使用目前仍存在的牆體建立安全路徑，並以路徑節點逐小步移動。

小怪更新流程會改為「遊蕩、追擊、返營」三狀態。只有存活玩家位於 520px 內且中心點連線沒有完整牆體時才取得目標；追擊目標死亡或超出距離後返營，回到營地再恢復遊蕩。每次更新都會從 `match.obstacles` 產生牆體快照；薄牆被既有規則破壞後，下一次小怪更新會偵測快照差異、清除舊路徑並使用最新地形重新尋路，厚牆仍保持阻擋。

## 技術背景

**語言／版本**：Python 3.11 或更新版本。

**主要相依套件**：現有 `pygame>=2.5,<3`；不新增第三方套件。尋路演算法使用 Python 標準函式庫與專案既有的 `Vector2`、`WorldRect`。

**儲存**：不新增持久化儲存。行為狀態、路徑、遊蕩點與牆體快照都保存於每場比賽的 `MatchState`／`MonsterState`。

**測試**：現有 `unittest` 測試集合；新增純尋路與怪物更新測試，並以 `python -m unittest discover -s pvpve_escape/tests -p "test_*.py"` 執行。Pygame 測試沿用現有的 headless 設定。

**目標平台**：Windows 桌面 Pygame 遊戲，啟動方式為 `python -m pvpve_escape`。

**專案類型**：單一 Python 桌面遊戲；世界更新集中在 `pvpve_escape/world.py`，資料模型集中在 `pvpve_escape/models.py`。

**效能目標**：正式遊戲主迴圈上限為 120 FPS；小怪更新仍以約 60 FPS 的穩定品質為目標，地圖整合驗收門檻為至少 55 FPS。固定 2400x1400 世界以 40px 網格約為 60x35、2100 個格子。每隻小怪只在取得新目標、目標／路徑節點改變、牆體快照改變或至少 0.25 秒到期時重算，避免每幀對所有小怪完整搜尋。

**限制**：最多 4 個營地、每營地 3 隻小怪與 6 名玩家；小怪半徑必須被納入牆體安全距離。所有移動仍須經既有碰撞與世界邊界限制，不得穿牆或傳送；返營在距營地中心 64px 內才算完成。固定地圖不需要可編輯導航網格，也不引入背景執行緒或新的導航套件。

**規模／範圍**：涵蓋 `CHASER`、`SHOOTER`、`BRUTE` 三種怪物及其現有攻擊規則；調整三類怪物的靜態移動速度平衡與玩家 0 號出生點；不改變玩家移動、玩家技能破牆規則、小怪彼此碰撞、傷害數值或投射物行為。

## Phase 1：設計與實作邊界

### 導航介面與演算法

`pvpve_escape/navigation.py` 提供可由 `world.py` 呼叫的純計算入口，概念介面為：

```text
find_grid_path(start, goal, radius, obstacles) -> tuple[Vector2, ...] | None
```

實作規則如下：

1. 以 `config.MONSTER_NAVIGATION_CELL_SIZE = 40` 將世界映射成 60x35 格；格中心若落在世界邊界的怪物安全內縮區外，或與「膨脹 `radius + clearance`」的固體牆矩形相交，就標為不可通行。這個矩形安全區與既有實際移動碰撞的膨脹矩形保持一致。
2. A* 使用八方向鄰接；斜向鄰居只有在終點格與兩個正交鄰居都可通行時才允許，禁止切過牆角。格子已以「怪物半徑加 clearance」膨脹牆體判定，A* 不對每條鄰接邊重複執行完整線段掃掠，以免多隻小怪在牆角觸發全圖掃描。啟發式使用八方向距離，節點排序加入固定座標次序以便測試重現。
3. 起點轉為最近的安全格；目標若落在牆內／不可通行格，或起點／目標沒有安全格，回傳 `None`。精確幾何線段檢查只用於實際起點到第一個節點、起點中心備援與安全目標的最後一段；實際移動仍由既有碰撞函式逐幀保護。若實際移動位置只進入規劃用的額外 clearance、但沒有進入 `radius` 的實體碰撞區，起點線段允許朝外離開 clearance，並再次以實體半徑掃掠確認沒有穿牆。
4. `world.py` 每次只朝下一個節點移動 `move_speed * delta_time * slow_multiplier`；距離節點不超過 `config.MONSTER_NAVIGATION_NODE_ARRIVAL_TOLERANCE=8` 時才取下一點。實際位移仍經 `move_circle_with_obstacles` 和 `clamp_position`。找不到路徑時清空節點、保持安全位置，於 `config.MONSTER_NAVIGATION_RETRY_INTERVAL=0.25` 秒後重試。

### 地形快照與改道

`update_world` 已在 `_handle_human_actions` 後才呼叫 `update_monsters`，因此同一更新週期內完成的薄牆破壞會先反映在 `match.obstacles`。`update_monsters` 在本次更新開始取得一次 `snapshot_obstacles(match.obstacles)`，並與 `MonsterState.navigation_obstacle_signature` 比較：

- 簽章改變時立刻清除 `navigation_path`、`navigation_goal` 與重算計時器，接著在同一隻怪物的行為更新中使用當前 `match.obstacles` 尋路。
- `snapshot_obstacles` 只包含 `solid` 牆體，因此已摧毀薄牆不再佔格，仍存在的薄牆和厚牆仍佔格。
- 路徑不只在牆體變動時重算；目標格改變、怪物走到下一個節點或 0.25 秒重算間隔到期時也會重算，避免玩家移動造成路徑過時。

### 行為、目標與戰鬥整合

1. `WANDER`：沒有目標時，在 `MONSTER_CAMP_POINTS[spawn_zone_id]` 周圍半徑 700px 內選擇安全候選點，以怪物 ID 與遞增索引產生穩定候選順序；以目前移速 50% 移動，抵達後以 `MONSTER_WANDER_PAUSE=0.75` 秒累計停留，允許一個 `delta_time` 的更新誤差。若目前位置超出 700px 遊蕩範圍則優先進入 `RETURN`。
2. `CHASE`：每次更新先保留仍存活且未超過 520px 的現有目標；沒有現有目標時，只從存活玩家中篩選距離 `<= 520` 且 `first_obstacle_on_segment` 不被未摧毀牆體阻擋者，依距離再依玩家 ID 選最近者。持續追擊時即使目標在牆後，也使用 A* 接近，而不是因牆後而解除已取得的目標。
3. `RETURN`：目標死亡或距離嚴格大於 520px 後清除 `target_player_id`，使用同一套導航回到所屬營地中心；距離中心 `<= MONSTER_CAMP_ARRIVAL_RADIUS`（64px）後轉為 `WANDER`。遊蕩與返營不執行接觸攻擊或發射投射物。
4. 只有 `CHASE` 且仍符合該怪物原本的攻擊距離時才進入既有攻擊區塊：`CHASER`／`BRUTE` 保留接觸傷害，`SHOOTER` 保留 420px 攻擊範圍、300px 偏好距離與慢速投射物。砲台蟲的偏好距離點先以目前固體牆和 `radius + clearance` 驗證；若點落在牆內，或雖然安全但 A* 找不到可達路徑，暫時以目標位置作為導航終點，讓 A* 先繞過牆角／封閉區域，再於後續重算恢復偏好距離。路徑重算不動態改變速度、半徑或攻擊計時器；靜態速度由設定表依規格統一計算，追獵獸為玩家基礎移速 90%，另外兩類套用相同相對增幅。
5. 重生時把行為設回 `WANDER`，清除目標、路徑、遊蕩點、停留計時與牆體簽章，位置回到原出生點，避免沿用死亡前狀態。

## 實作階段

1. **設定與資料狀態**：在 `config.py` 集中新增導航、警戒、遊蕩、返營到達與重算間隔常數，並設定三類怪物速度平衡與玩家 0 號出生點；在 `models.py` 新增 `MonsterBehavior` 和 `MonsterState` 的運行欄位；確認 `monsters.py` 建立與重生預設可回到 `WANDER`。
2. **純導航模組**：建立 `navigation.py`，完成世界／格子轉換、固體牆佔用、A*、禁止斜角切入、路徑段安全檢查與無路徑回傳；先以單元測試驗證矩形牆、厚薄牆、邊界、半徑與不可達情況。
3. **世界更新狀態機**：重寫 `update_monsters` 的目標選擇與移動部分，加入快照失效、遊蕩候選、返營、節點跟隨及重試；把攻擊保留在追擊狀態並補足重生清理。
4. **回歸與可觀察驗證**：執行全套 `unittest`、編譯檢查與快速開始中的手動情境；確認所有三種怪物可繞牆、薄牆破壞後下一更新改道、厚牆仍阻擋，以及既有攻擊／投射物測試不回歸。

## 測試策略

- **純函式測試**：測試格子尺寸與邊界、圓形半徑安全內縮、八方向 A* 可繞牆、禁止牆角切入、目標／起點不可通行與無路徑安全回傳。
- **狀態測試**：建立最小 `MatchState` 與障礙，逐幀呼叫 `update_monsters`，驗證三種怪物各自進入追擊、離開後返營、距營地中心 64px 內回營後遊蕩、死亡後重生清理，以及遊蕩期間不攻擊。
- **量化測試**：以全新 `MatchState` 重複執行 20 次追擊與 20 次遊蕩案例；每次追擊先讓怪物在 520px 內且無牆視線下合法取得目標，再將目標移到牆後，並在 10 秒內完成；遊蕩每種怪物每次抵達至少兩個不同點，並以 100% 成功斷言作為 SC-001／SC-004 的通過條件。非重生單幀位移須不超過 `move_speed * delta_time * slow_multiplier + config.TERRAIN_GEOMETRY_EPSILON`。
- **地形變動測試**：先讓路徑繞過薄牆，再設定 `destroyed=True`，下一次更新確認路徑簽章更新且方向可利用缺口；同時確認厚牆仍不能被路徑穿越。
- **戰鬥回歸測試**：確認 `CHASER`／`BRUTE` 仍只在接觸範圍造成傷害，`SHOOTER` 仍在偏好距離與攻擊範圍內產生原本的慢速投射物。
- **平衡與出生點測試**：確認追獵獸為玩家基礎移速 90%，其它怪物套用相同相對增幅，遊蕩候選可使用 700px 半徑，且玩家 0 號與營地中心／實際怪物出生點均至少相距 200px。
- **完整驗證**：執行 `python -m unittest discover -s pvpve_escape/tests -p "test_*.py"`、`python -m compileall -q pvpve_escape` 與 `git diff --check`；再按 `quickstart.md` 手動啟動一次遊戲。

## 風險與控制

| 風險 | 控制方式 |
|---|---|
| 網格中心可通行但節點連線仍擦到牆角 | 佔格加入怪物半徑與 4px clearance，斜向鄰接檢查兩個正交格並禁止切角；實際起點／目標段落另做精確檢查，逐幀移動仍由地形碰撞保護。 |
| 破牆後沿用舊路徑 | 使用每次更新的 `snapshot_obstacles`；簽章差異優先於一般重算計時器並清空舊節點。 |
| 目標在偵測邊界造成狀態抖動 | 使用明確的 `<= 520` 取得／保留與 `> 520` 解除規則，同一更新只執行一次狀態轉換，並在測試中覆蓋邊界。 |
| 找不到路徑時以碰撞修正卡在牆前 | 不強制直線目標方向；無路徑時安全停留並依重算間隔重試，不改寫位置。 |
| 砲台蟲偏好距離點落在牆角或封閉區 | 先驗證偏好點；若偏好點落在牆內，或偏好點安全但 A* 找不到路徑，則以目標位置作暫時可達終點。若實際位置只位於額外 clearance，離開首段仍以實體半徑掃掠確認不穿牆。 |
| 導航改動影響既有攻擊 | 攻擊條件留在 `CHASE` 的既有類型分支，加入三種怪物的回歸測試。 |
