# 任務：PvPvE 中央撤離競技遊戲

**輸入**：`specs/001-pvpve-escape-game/` 下的 `spec.md`、`plan.md`、`research.md`、`data-model.md` 與 `quickstart.md`。

**前置條件**：完成計畫與資料模型；本功能沒有外部 API 或 `contracts/`。

**測試策略**：使用 Python 標準函式庫 `unittest` 驗證純規則，並依 `quickstart.md` 執行視窗手動驗證。每個使用者故事的測試任務必須先於該故事的實作任務完成。

**執行原則**：每個任務完成後執行對應測試或啟動程式；保留可執行版本，再進入下一個任務。

## 任務格式

- `[P]`：可與同階段其他任務平行執行，且不會修改同一個檔案。
- `[US1]`、`[US2]`、`[US3]`：對應 `spec.md` 中的使用者故事。
- 每一項任務都包含明確的任務編號與檔案路徑。

## 依賴與執行順序

### 階段依賴

- **階段 1**：無前置依賴；T002 依賴 T001 的依賴檔，T003 可與 T001 平行。
- **階段 2**：依賴階段 1；T010 依賴 T004～T009，T011 依賴所有基礎建設任務。
- **階段 3／使用者故事 1**：依賴階段 2；T012～T013 必須先完成，再執行 T014～T019。
- **階段 4／使用者故事 2**：依賴使用者故事 1；T021～T023 必須先完成，再執行 T024～T031。
- **階段 5／使用者故事 3**：依賴使用者故事 2；T033～T034 必須先完成，再執行 T035～T040。
- **階段 6**：依賴三個使用者故事完成；T044～T047 是最終交付關卡。

### 使用者故事依賴

- **使用者故事 1（P1）**：依賴基礎建設；是最小可玩版本，提供選擇、6 人狀態、地圖、移動與鏡頭。
- **使用者故事 2（P1）**：依賴使用者故事 1 的玩家、世界與主迴圈；加入戰鬥與生命週期，不改變既有選擇與移動規則。
- **使用者故事 3（P1）**：依賴使用者故事 2 的玩家生命狀態與遊戲計時；加入撤離勝負，不改變多人同區的個別進度規則。

### 可平行工作

- T001 與 T003 可在階段 1 平行執行；T002 必須等待 T001。
- T004 與 T005 可在階段 2 平行執行；T006～T010 依其輸入介面順序完成。
- 使用者故事 1 的測試 T012 與 T013 可先後加入同一測試檔，但不可與修改同一檔案的實作任務平行。
- 使用者故事 2 的角色資料整理可先完成於 T024，規則實作 T025 與角色攻擊 T026 必須依模型介面完成後再整合。
- 使用者故事 3 的規則測試 T033～T034 可在同一測試檔中連續建立；T037 的繪製與 T038 的控制器可以在 T035～T036 的規則介面穩定後分開處理。
- T042 與 T043 可在整合程式穩定後平行執行；T044～T047 必須依序完成。
