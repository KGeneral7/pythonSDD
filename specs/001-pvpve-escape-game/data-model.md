# 資料模型與狀態設計：PvPvE 中央撤離競技遊戲

## 1. 比賽資料

### `MatchState`

代表一場比賽的全域狀態。

| 欄位 | 型別 | 說明與限制 |
|---|---|---|
| `phase` | `MatchPhase` | `CHARACTER_SELECT`、`PLAYING`、`VICTORY` 或 `NO_WINNER` |
| `elapsed_time` | `float` | 已經過秒數，範圍為 0～240 秒 |
| `duration` | `float` | 固定為 240 秒 |
| `extraction_start_time` | `float` | 固定為 210 秒 |
| `extraction_required_time` | `float` | 固定為 10 秒 |
| `extraction_zone` | `CircleZone` | 地圖中央撤離區，首版半徑 140 世界單位 |
| `players` | `list[PlayerState]` | 固定 6 名玩家，識別字為 0～5 |
| `monsters` | `list[MonsterState]` | 首版 4 個生成區、每區 3 隻 |
| `winner_id` | `int | None` | 勝利階段保存勝者識別字 |
| `developer_mode` | `DeveloperModeState` | F1 開關的測試工具狀態 |

### 比賽狀態轉換

```text
CHARACTER_SELECT
        │ 完成角色與配件選擇
        ▼
PLAYING ────────────────┐
   │                    │
   │ 有玩家完成撤離     │ 計時到 240 秒且無勝者
   ▼                    ▼
VICTORY              NO_WINNER
```

- 只允許 `PLAYING` 更新玩家、怪物、傷害與撤離進度。
- 進入 `VICTORY` 或 `NO_WINNER` 後停止遊戲更新，只保留重新開始與離開操作。
- 同一更新週期中，先依玩家識別字排序檢查撤離完成，再檢查比賽時間是否結束；因此同幀完成撤離時結果可重現。

### `CircleZone`

代表以圓形邊界描述的世界區域。

| 欄位 | 型別 | 說明與限制 |
|---|---|---|
| `center` | `tuple[float, float]` | 世界座標中的圓心；首版中央撤離區為 `(1200, 700)` |
| `radius` | `float` | 必須大於 0；首版中央撤離區為 140 世界單位 |

- `contains(point)` 判定點到 `center` 的距離是否小於或等於 `radius`。
- `CircleZone` 只保存幾何資料與包含判定，不直接修改玩家或比賽狀態。
- `MatchState.extraction_zone` 使用此型別；撤離規則另外依比賽時間與玩家人數處理進度。

## 2. 玩家資料

### `PlayerState`

| 欄位 | 型別 | 說明與限制 |
|---|---|---|
| `player_id` | `int` | 0～5，唯一識別字；也用於同幀勝負裁決 |
| `controller_type` | `ControllerType` | `HUMAN` 或 `DUMMY` |
| `character_id` | `CharacterId` | 六種角色之一，單局內不重複 |
| `tactical_id` | `TacticalId` | `DASH`、`SHIELD` 或 `CONTROL` |
| `position` | `Vector2` | 世界座標中的玩家中心位置 |
| `spawn_position` | `Vector2` | 玩家目前的外圍安全出生位置 |
| `radius` | `float` | 玩家碰撞半徑，首版 18 世界單位 |
| `base_max_health` | `float` | 一般角色 100；守衛者由被動提高 20% |
| `max_health` | `float` | 依角色被動與強化層數計算 |
| `health` | `float` | 範圍為 0～`max_health` |
| `move_speed` | `float` | 一般角色 220；追獵者由被動提高 15% |
| `upgrade_stacks` | `int` | 範圍為 0～10 |
| `ultimate_energy` | `float` | 範圍為 0～100 |
| `ammo` | `int` | 範圍為 0～`ammo_capacity` |
| `ammo_capacity` | `int` | 依角色設定為 2～4 |
| `ammo_recovery_timer` | `float` | 持續補彈計時，不因彈匣未耗盡而停止 |
| `tactical_cooldown` | `float` | 範圍從設定值倒數至 0 |
| `primary_cooldown` | `float` | 專屬普攻的攻擊間隔 |
| `death_timer` | `float` | 死亡後 5 秒重生倒數 |
| `alive` | `bool` | 死亡期間為 `False` |
| `extraction_progress` | `float` | 個人撤離進度，範圍為 0～10 秒 |
| `developer_placed` | `bool` | 是否由開發者模式放入中央撤離區 |

### 玩家不變條件

- `upgrade_stacks` 不得超過 10；每層倍率為 `1 + 0.03 × upgrade_stacks`。
- 攻擊力使用角色攻擊基礎值乘以強化倍率，再套用角色被動。
- 最大生命值使用角色基礎生命值乘以角色被動倍率與強化倍率。
- 生命值不得小於 0 或大於最大生命值。
- 大招能量不得小於 0 或大於 100；傷害能量在 100 封頂。
- 彈藥不得小於 0 或大於彈匣容量；每次恢復只增加一發。
- 玩家死亡時立即將 `health`、`upgrade_stacks`、`ultimate_energy` 與 `extraction_progress` 重置為死亡狀態需要的值；5 秒後重新初始化至安全出生點。
- 假玩家不讀取人類輸入，也不主動移動或攻擊；但其生命、受傷、死亡、重生與撤離進度仍由一般規則處理。

### 玩家狀態轉換

```text
ALIVE ── health <= 0 ──► DEAD
  ▲                       │
  │ death_timer >= 5 秒   │
  └──── RESPAWNING ◄──────┘
```

死亡玩家不能攻擊、累積撤離或被判定為撤離區內的競爭者。重生完成後回到 `ALIVE`，強化與大招能量從零開始。

## 3. 角色資料

### `CharacterDefinition`

角色資料包含 `character_id`、顯示名稱、基礎數值、彈匣設定、專屬普攻、被動與大招效果。六種首版初始值如下：

| 角色 | 專屬普攻初值 | 彈匣／補彈 | 被動初值 | 大招初值 |
|---|---|---|---|---|
| 破陣者 | 60° 扇形、5 顆彈丸，每顆 8 傷害，射程 180 | 3 發／0.45 秒 | 180 內傷害 +20% | 半徑 180、50 傷害、擊退 |
| 狙擊者 | 蓄力 0.6 秒，單發 45 傷害，射程 900 | 2 發／0.80 秒 | 超過 450 距離傷害 +20% | 直線射程 1000、80 傷害、穿透 |
| 守衛者 | 前方近戰弧形，25 傷害、擊退 120 | 2 發／0.60 秒 | 最大生命值 +20% | 4 秒內減傷 70% |
| 追獵者 | 回旋飛刃，往返各可造成 18 傷害，最遠 300 | 3 發／0.35 秒 | 移速 +15% | 突進 320、0.5 秒免傷、路徑 40 傷害 |
| 控場者 | 重力地雷，18 傷害、半徑 100、減速 50% 持續 1.5 秒，最多 2 個 | 2 發／0.55 秒 | 控制時間 +50% | 半徑 170、減速 70%、定身 0.75 秒、持續 3 秒 |
| 吸能者 | 近距離持續光束，每 0.15 秒 7 傷害，最遠 260，最多引導 1.2 秒 | 4 發／0.20 秒 | 對怪物傷害的大招能量 +25% | 半徑 200、50 傷害、恢復造成傷害的 50% |

- 所有角色的傷害都先套用強化倍率，再依角色被動計算；有效傷害才轉換為大招能量。
- 大招沒有獨立冷卻；只有能量充滿才可使用。
- 普攻的彈藥補回在彈藥低於容量時持續進行，不需等到彈藥歸零。

## 4. 戰術配件資料

### `TacticalDefinition`

| 配件 | 首版效果 | 冷卻 |
|---|---|---|
| 短距離衝刺 | 朝移動方向或瞄準方向移動 220，並免疫傷害 0.2 秒 | 12 秒 |
| 短時間護盾 | 吸收最多 60 點傷害，持續 2 秒 | 12 秒 |
| 範圍控場 | 半徑 100 的區域，讓目標減速 60%，持續 1.5 秒 | 12 秒 |

- 戰術配件開局即可使用，選定後該局不可切換。
- 建立比賽時，玩家 0 使用人類玩家選定的 `tactical_id`；玩家 1～5 依玩家識別字循環指派 `DASH`、`SHIELD`、`CONTROL`，因此六名玩家都具備明確且可使用的配件。
- 配件效果與角色大招分開保存；使用配件不會消耗大招能量。
- 玩家死亡時配件冷卻重置為可使用狀態。

## 5. 怪物資料

### `MonsterState`

| 欄位 | 型別 | 說明與限制 |
|---|---|---|
| `monster_id` | `int` | 單局唯一識別字 |
| `spawn_zone_id` | `int` | 4 個生成區之一 |
| `position` | `Vector2` | 世界座標 |
| `radius` | `float` | 首版 16 世界單位 |
| `max_health` | `float` | 首版 50 |
| `health` | `float` | 範圍為 0～`max_health` |
| `move_speed` | `float` | 首版 80 世界單位／秒 |
| `slow_timer` | `float` | 控場減速剩餘時間 |
| `slow_multiplier` | `float` | 控場移速倍率，範圍為 0～1 |
| `root_timer` | `float` | 定身剩餘時間；大於 0 時停止移動 |
| `target_player_id` | `int | None` | 目前追擊目標 |
| `attack_timer` | `float` | 接觸攻擊間隔，首版每 1 秒一次 |
| `respawn_timer` | `float` | 死亡後 6 秒重生倒數 |
| `last_damage_player_id` | `int | None` | 最後造成有效傷害的玩家 |

- 每個生成區首版維持 3 隻怪物，死亡後在原生成區重生。
- 怪物接觸攻擊首版造成 10 點傷害。
- 怪物可受到減速與定身；控制計時到期後恢復正常移動，重生不保留上一條生命的控制狀態。
- 怪物重生不保留上一隻怪物的最後傷害來源。
- 只有玩家造成的最後有效傷害能取得怪物強化；環境或沒有歸屬的傷害不給予強化。

## 6. 傷害事件

### `DamageEvent`

短生命週期的戰鬥事件，供傷害、能量與最後一擊判定使用。

| 欄位 | 說明 |
|---|---|
| `sequence` | 本次更新週期中的遞增事件序號 |
| `source_player_id` | 傷害來源玩家；怪物傷害可為 `None` |
| `target_id` | 受傷的玩家或怪物識別字 |
| `raw_damage` | 套用防禦前傷害 |
| `effective_damage` | 實際扣除生命的傷害 |
| `created_at` | 世界時間 |

- 大招能量依 `effective_damage` 增加。
- 怪物生命降至 0 時，使用該怪物最後一筆有效玩家傷害的來源作為最後擊殺者。
- 同一更新週期中的事件依 `sequence` 排序，避免最後一擊結果依賴集合迭代順序。

## 7. 撤離資料與規則

### `ExtractionProgress`

撤離進度直接保存於 `PlayerState.extraction_progress`，不建立全域共享進度。

- 撤離區在 `elapsed_time >= 210` 時啟用。
- 存活玩家位於中央圓形區域內時，每秒增加 `delta_time`。
- 玩家離開區域、死亡或比賽結束時，該玩家進度歸零或停止使用。
- 多名玩家同區不會互相阻塞，每名玩家獨立累積。
- 進度達到 10 秒即建立勝利候選，依 `player_id` 排序檢查；第一個完成者成為勝者。
- 同一更新週期同時達標時，較小 `player_id` 先裁決。
- 勝利檢查先於時間到檢查；如果在 240 秒同一更新週期達標，完成撤離者獲勝。

## 8. 開發者測試狀態

### `DeveloperModeState`

| 欄位 | 說明 |
|---|---|
| `enabled` | F1 開關 |
| `selected_dummy_id` | 目前選取的假玩家 |
| `show_overlay` | 是否顯示測試提示 |

- 開啟後使用數字鍵 1～5 選取假玩家。
- 使用 `M` 將選取的假玩家放到中央撤離區。
- 使用 `N` 將選取的假玩家送回其外圍出生點。
- 測試控制只改變假玩家位置，不改變撤離規則本身。

## 9. 座標與繪製資料

### `Vector2`

代表世界座標中的二維位置或方向。

| 欄位 | 型別 | 說明與限制 |
|---|---|---|
| `x` | `float` | 世界水平座標；原點位於地圖左上角 |
| `y` | `float` | 世界垂直座標；原點位於地圖左上角 |

- 玩家、怪物、出生點、投射物、技能效果與撤離區圓心都使用世界座標。
- 實作可使用 `pygame.Vector2` 或等價的二維資料結構，但跨模組介面必須維持相同的 `x`、`y` 語意。

### `Camera`

保存人類玩家視角的世界範圍。

| 欄位 | 型別 | 說明與限制 |
|---|---|---|
| `position` | `Vector2` | 鏡頭左上角世界座標，會被限制在世界邊界內 |
| `viewport_size` | `Vector2` | 視窗尺寸 `(1280, 720)` |
| `world_size` | `Vector2` | 世界尺寸 `(2400, 1400)` |

- 鏡頭跟隨玩家 0，並限制位置不顯示世界外的有效遊戲區域。
- 將物件世界座標減去 `position` 即可轉為畫面座標。

- 世界尺寸為 2400×1400；視窗尺寸為 1280×720。
- 角色、怪物、子彈、技能範圍與撤離區使用幾何圖形繪製；顏色與尺寸由設定集中管理。
- 繪製不修改遊戲狀態；所有狀態變更在更新階段完成。
