# 戰鬥回饋與 GUI 介面契約

本契約描述玩家可觀察的輸入、效果與狀態回饋。它不是網路 API；它約束 `pvpve_escape` 內控制器、世界規則與渲染器之間的資料語意，讓自動化測試與人工驗收使用相同的可觀察結果。

## 輸入契約

| 輸入 | 來源 | 行為 | 可觀察回饋 |
|---|---|---|---|
| `W/A/S/D` | 鍵盤 | 移動，受世界邊界限制 | 玩家位置與鏡頭同步更新 |
| 滑鼠／右類比 | 指標 | 產生瞄準方向 | 方向線端點落在世界邊界內 |
| 左鍵 | 滑鼠 | 依角色觸發普攻或蓄力；放開時施放非引導普攻 | 對應唯一主攻特效；普攻狀態期間彈藥凍結 |
| 右鍵 | 滑鼠 | 施放大招（能量滿時） | 對應大招特效、能量歸零、有效規則效果 |
| `Space` | 鍵盤 | 使用配件（冷卻完成時） | 對應配件特效、實際位移／防禦／控場與倒數 |
| `1～6`、`Q/W/E`、`Enter` | 鍵盤／選角畫面 | 選擇角色、選擇配件並開始比賽 | 選取框、角色／配件名稱與開始狀態一致 |
| 選角／配件按鈕 | GUI | 選擇角色與配件 | 卡片選取狀態與角色／配件圖示清楚可辨 |

## 普攻視覺契約

每個 `primary_kind` 都必須建立至少一個與其他角色不同的效果，並且效果存在期間有明確位置、方向或範圍。最低辨識要求如下：

| 角色 | 主攻視覺 | 規則對應 |
|---|---|---|
| 破陣者 | 60° 填色扇形、五條短散射軌跡、命中脈衝 | `breach_cone` 僅作視覺包絡；五個 `breach_pellet` 各自負責碰撞與單顆傷害 |
| 狙擊者 | 蓄力瞄準線、細長高亮子彈、命中十字閃光 | 線段／高速 projectile 連續碰撞 |
| 守衛者 | 盾形弧線與向前脈衝 | 盾弧範圍／減傷規則 |
| 追獵者 | 刀刃多邊形與短殘影 | 近戰方向命中／位移規則 |
| 控場者 | 發射小型裝置與落點環 | 裝置／範圍控制規則 |
| 吸能者 | 連接施放者與目標的吸取線、節奏脈衝 | 持續傷害與生命轉換規則 |

效果在畫面上必須與實際攻擊方向一致；只顯示特效但不建立對應傷害／控制的路徑視為契約違反。

## 大招與配件視覺契約

| 類別 | 最低視覺要求 | 最低規則要求 |
|---|---|---|
| 六種大招 | 每種使用唯一的範圍輪廓、光束、脈衝、投射物或護盾組合 | 能量滿才能施放；施放後歸零；對玩家／怪物有規格定義的效果 |
| `TacticalId.DASH` | 起點閃光、位移殘影、終點脈衝 | 角色位移且不超出邊界 |
| `TacticalId.SHIELD` | 包覆角色的盾弧與減傷脈衝 | 持續期間降低受傷或依定義阻擋傷害 |
| `TacticalId.CONTROL` | 位置固定的圓形控場區、網格與向內脈衝 | 控制範圍內目標確實受限；冷卻開始並倒數 |

大招／配件效果的 alpha 可與世界特效不同，但不能被 GUI 面板 alpha 靜默降低；技能前景必須保持清晰。

## 破陣者命中契約

### 施放資料

```text
shape            = sector_sweep_with_pellets
angle            = 60 degrees
range            = 200 world units
pellets          = 5 independent damaging projectiles
damage_per_pellet = 7 base damage
pellet_radius    = 16 world units
visual_cone      = 1, visual_only
```

### 命中行為

1. 五顆散彈共用施放時角色位置為原點，並依施放時瞄準方向及固定角度偏移建立五條路徑。
2. 每顆散彈使用半徑 16，並以自身上一幀至本幀的連續線段檢查目標碰撞圓是否相交；這個半徑要讓 60° 包絡內相鄰路徑的間隙被覆蓋，目標距離超過 200（含碰撞半徑擴張）時不得命中。
3. 同一顆散彈對同一目標最多造成一次單顆傷害；五顆都相交時才會得到 `5 * 7` 的基礎傷害，命中 `k` 顆則為 `k * 7`，再套用既有修正。
4. 視覺 `breach_cone` 即使覆蓋目標，也不得自行造成傷害；只有實際 `breach_pellet` 碰撞才算命中。
5. 目標死亡後，後續散彈只可產生無效／跳過結果，不得把生命降到零以下或觸發額外擊殺事件。
6. 五條路徑之外、散射包絡外或射程外的目標不得命中；路徑邊界的部分相交依碰撞圓判定。

## 彈藥契約

| 狀態 | `ammo` | `ammo_recovery_timer` |
|---|---|---|
| 普攻按住 | 不變 | 重置為 0 |
| 普攻蓄力中 | 不變 | 重置為 0 |
| 普攻冷卻／後搖中 | 不變 | 重置為 0 |
| 普攻完全停止、存活且未滿彈 | 按間隔逐發增加 | 累積至間隔並扣除 |
| 已滿彈 | 不變 | 0 |
| 大招／配件單獨使用 | 依普通恢復規則 | 不因大招／配件而阻擋 |
| 死亡／重生流程 | 不回彈 | 依死亡／重生初始化 |

解除普攻狀態的第一幀不視為已等待完成；玩家必須停止完整恢復間隔後才看到下一發彈藥。

## GUI 透明度契約

### 設定

```text
GUI_OPACITY_PERCENT: integer, default 78, inclusive range 50..90
panel_alpha = round(255 * GUI_OPACITY_PERCENT / 100)
```

輸入 49 應使用 50，輸入 91 應使用 90；沒有設定值時使用 78。設定只影響面板／卡片／血條背景，不影響世界背景、角色、怪物、瞄準線、技能前景、文字或血條填色。

### 套用元件

- 角色與配件選擇卡。
- HUD 面板與玩家名單。
- 遊戲結果／撤離結果面板。
- 玩家與怪物血條的背景框。

每個面板使用自己的 `SRCALPHA` surface；面板相互重疊時維持正常 alpha 合成，不能以全螢幕 overlay 代替。

## 錯誤與拒絕回饋

| 條件 | 規則結果 | 玩家可觀察結果 |
|---|---|---|
| 彈藥為零 | 普攻不建立傷害 action | 不會出現假的命中特效；可繼續移動與瞄準 |
| 大招能量未滿 | 不施放 | 能量條維持目前值，不消耗 |
| 配件冷卻中 | 不施放 | 冷卻數字持續倒數，不建立重複控制 |
| 破陣者散彈路徑／距離外 | 不命中 | 不顯示傷害數字／受擊反饋 |
| 視覺-only cone 覆蓋目標 | 不套用規則 | 只更新扇形標記，不改變血量 |
| 實際 pellet 路徑穿過目標 | 套用一次單顆傷害 | 依命中顆數顯示受擊／命中回饋 |
| GUI alpha 超出範圍 | 鉗制到 50 或 90 | 面板仍可讀，不使世界前景變淡 |

## 驗收對應

- **AC-001**：六角色、六大招、三配件各產生可區分且可見的 effect。
- **AC-002**：扇形中心、邊界、目標半徑、超距離與多目標情境符合命中契約。
- **AC-003**：攻擊輸入／蓄力／冷卻期間彈藥完全不增加，停止後完整等待才恢復。
- **AC-004**：50、78、90 與越界設定下，面板半透明而文字與戰鬥前景清晰。
