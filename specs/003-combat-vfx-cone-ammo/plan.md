## 摘要

本功能在既有 Pygame PvPvE 原型上補齊四項可驗證的戰鬥體驗：六名角色與三種配件都必須有清楚且可區分的攻擊／技能特效；破陣者的攻擊必須建立五顆獨立散彈，使用 60°、200 距離作為散射包絡與預覽，並依實際命中顆數計傷；角色處於普攻蓄力、持續攻擊或普攻後搖期間時不得恢復彈藥；所有遊戲面板改由可配置的半透明背景繪製，同時保持文字、角色、怪物、瞄準線與技能前景清晰。

設計會延伸現有的 `CombatAction`、`AbilityEffect`、角色定義、世界更新與渲染分層，不新增引擎、素材或網路依賴。破陣者建立一個視覺用 `breach_cone` 標記與五個權威 `breach_pellet` 投射物；五條畫面軌跡就是五顆實際傷害來源，每個目標依真正相交的彈道數量計算傷害。彈藥恢復則在輸入與普攻狀態決定後才執行，並在被阻擋時重置恢復計時器，使攻擊停止後必須等待完整恢復間隔。

## 實作設計

### 1. 動作、效果與渲染資料流

輸入先由遊戲控制器轉成 `CombatAction`，再由世界規則建立 `AbilityEffect` 或直接套用傷害。`AbilityEffect` 新增明確的 `origin`，並以 `position` 表示當前前端、`previous_position` 表示上一幀前端、`distance_travelled` 表示掃掠進度。渲染器只依 `effect.kind` 與 metadata 畫出軌跡／範圍，永不再次決定傷害。

所有移動型效果沿用上一幀到本幀的連續線段檢查，避免高速子彈穿透目標；視覺-only effect 明確標記 `metadata["visual_only"] = True`，更新器不得對其執行傷害或控制。

### 2. 破陣者五顆獨立散彈

破陣者一次普攻建立一個視覺用 `breach_cone` 標記與五個權威 `breach_pellet` effect：

- 五者共用施放當下的原點、方向、60° 散射包絡、200 最大距離與 900 速度；每顆散彈碰撞半徑為 16，確保最遠距離的相鄰路徑間隙仍由目標碰撞圓覆蓋。
- `breach_cone` 只繪製填色扇形與施放範圍，標記 `visual_only`，不得呼叫傷害或能量規則。
- 五個 `breach_pellet` 依固定角度偏移形成五條實際直線路徑；每顆都有 `pellet_index`、獨立位置／前端與自己的 `hit_target_ids`。
- 每顆投射物使用上一幀到本幀的連續線段，依目標碰撞圓與放大後散彈半徑相交判定命中；同一顆對同一目標最多一次。
- 每次實際命中呼叫既有單顆傷害與強化修正，因此目標命中 `k` 顆時得到 `k * 7` 的基礎傷害（再套用既有角色修正）；目標死亡後後續散彈不再造成有效傷害。
- 五顆投射物依 `BLOCK` 共同在第一面牆前停止，不移除薄牆或草叢；視覺扇形與實際投射物採同一路徑資料。

60°、200 距離仍是瞄準預覽與五條路徑的包絡範圍，不代表包絡內每一點都自動命中；傷害只來自實際穿過目標的散彈。

### 3. 普攻期間彈藥恢復

將生命／重生／冷卻更新與彈藥恢復拆成明確階段。每幀順序為：玩家生命週期與冷卻 → 處理輸入並建立普攻狀態 → 判定 `primary_attack_active` → 受條件控制的彈藥恢復 → 效果碰撞與生物更新 → 撤離判定。

`primary_attack_active` 只在玩家存活且符合下列任一條件時成立：

- 普攻按鍵仍按住。
- 普攻蓄力值大於零。
- 普攻後搖／普攻冷卻大於零。

若成立，`recover_ammo` 不增加彈藥、不增加恢復計時器，並把計時器重置為零；阻擋狀態解除後，必須再經過完整恢復間隔才補回一發。大招或配件單獨使用不阻擋彈藥恢復；長時間存在的地雷、回旋鏢或其他效果也不延長普攻阻擋，阻擋只依角色普攻本身的輸入／蓄力／冷卻。

### 4. 六角色、六大招與三配件的可讀特效

使用固定幾何圖形與角色色盤，不使用隨機粒子或外部圖片。每種主攻至少有一個唯一的形狀／動態語彙：破陣者為扇形與五條散射軌跡、狙擊者為蓄力線與高亮穿透線、守衛者為盾弧與脈衝圈、追獵者為刀刃與殘影、控場者為地雷環／網格、吸能者為吸取連線與脈衝。六種大招與三種配件分別使用不同的範圍輪廓、方向指示、護盾／位移殘影或控制脈衝。

渲染順序固定為：世界背景 → 地圖／怪物 → 移動中的技能特效 → 瞄準線 → 玩家與血條前景 → HUD／選單。特效過期與物件死亡時要立即移除，避免畫面殘留；幾何顏色與 alpha 只影響視覺，不改變規則數值。

### 5. 半透明 GUI

新增 `GUI_OPACITY_PERCENT` 共用設定，預設 78，允許值 50～90；超出範圍時在載入／設定入口鉗制到合法範圍。面板、選角卡、配件卡、HUD、玩家名單、結果面板與血條背景各自建立 `pygame.SRCALPHA` surface，以設定值套用背景 alpha；不要在整個畫面上覆蓋一層半透明色塊。文字、角色／怪物圖像、瞄準線、技能前景與血條填色維持不透明或原有高對比度。

### 6. 驗證策略

先補齊純規則測試：五條散彈路徑中心／路徑間／外側／超距離、目標半徑擴張、命中顆數對應傷害、每顆最多一次、視覺扇形標記不傷害、攻擊輸入與普攻冷卻期間的彈藥凍結、解除後完整等待間隔、死亡／重生清除狀態。再加入世界整合測試確認各角色 effect kind 與傷害資料流。最後以無頭渲染 smoke test 驗證所有角色／大招／配件都能建立 surface，並以 quickstart 的人工情境確認畫面辨識度與 GUI alpha。
